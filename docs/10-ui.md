# 10 · UI

Screens for non-technical creators. Mocks live in the *Orchestrator UI Mocks* design canvas (run mode: Episode builder, Shot node, Review inbox, Library; build mode: Recipe builder, Canvas view).

## Design principles

1. **The run is a live graph; reviews are screens.** Home is the run as its recipe's graph: each step a box with its live state (white AI step, amber "you decide", grey tool), loops as dashed arrows with their limit, a for-each step as a strip you click into ([D-67](17-decisions.md), which replaced "steps and reviews, not nodes and edges" as the default). Clicking a step that waits on you opens its review screen, which stays a screen, not more graph. The vertical recipe in plain words stays as an alternative view for creators who don't think in graphs.
2. **Screens are generated, not designed.** Creators pick a review style; the platform renders the screen from what the step produces (images → grid, audio → players, video → player with trim).
3. **Plain-language instructions with @mentions**, never `{{variables}}` in the creator UI. "Draw @Mitra pouring chai for @Pinki at the @ChaiStall, in @Style".
4. **"Keep consistent"** instead of "locked assets".
5. **Trust in words:** Ask me · Decide for me when confident · Always decide.
6. **Costs in dollars before running**, and a spending cap.
7. **Phone-first review.** Creators pick panels and approve voices on their phones. In v0.1 the local web app is reachable over the home network with a pairing token; a PWA with offline review and push notifications comes with hosting in v0.4 ([D-38](17-decisions.md)).
8. **Plain-language errors with a suggested fix**, never a stack trace.
9. **Accessible:** real buttons and inputs, 44 px touch targets, every drag has a non-drag alternative, text contrast ≥ 4.5:1.

## Run mode

### Episode view (recipe with status)

```
Mohalla Mitra › Story 1: Tanker Raja › Part 3: The trap closes        Spent $— · Cap $—   [5 waiting for you]

[Change waiting for your OK: "Make Tiwari sweatier in every shot" — redo 4 shots; P3-08 is locked, its clip will go stale]  [Review plan]

2 Break it into shots        12 shots, 4 to animate                    Locked
3 Draw each shot             3 options · you pick                      7 of 12 locked  ■■■▲▲■■□▲■■·
4 Animate the big moments    4 clips · AI checks faces                 Starts as shots lock
5 Record the voices          each line · you listen                    Not started
6 Add music and put it together                                        Automatic
7 Watch the Reel, then post  approve or list fixes · posting checklist You
                                                       Chat: Episode agent · Part 3 (directs every step)
```

### Node view (one shot)

- Breadcrumb `Mohalla Mitra › Tanker Raja › Part 3 › Shot P3-04`; context mode (Local/Full/Isolated) and trust selectors.
- Large preview of the current version with a marked edit area.
- **Version tree**: Main (A, B, C → C2 current); Branch "night version" (N1, parked, not in context).
- Actions: **Lock C2 · Edit · Crop · Try again · Branch off**.
- **What this uses** chips: Using (P3-04 · version C), Target (@Bheem + marked area), Added (@Bheem · look ✕, + Add asset), Rule (proven edit wording added).
- Chat scoped to the shot ("can change only this shot"), with check results (✓ one of each character, ✓ gamcha present, ✓ no readable text) and a **knowledge-base tip** ("Bheem's gamcha has gone missing 3 times. Add 'always wearing his gamcha' to his look?" → Add to Library / Not now).

### Review inbox (phone)

- Header: back to Part 3, "Shot 4 of 5 waiting", progress bar.
- Large preview, 3 option thumbnails (A/B/C radio), "In this shot" chips, "✓ Pre-checked: right characters, no extras, no text".
- Note box ("What to change, for Edit or Try again").
- Footer: **Lock B** (primary) and Edit / Crop / Try again.
- Batching: all shots of a stage reviewed on one screen; the graph continues per shot as each is submitted.

### Library

- Left list: Characters (each with "Consistent" or "Needs a look" e.g. Inspector Tiwari), Places, Series (Style, Music kit, Rules), + Add to Library.
- Entity page (@Mitra): description, "Keep consistent" toggle, facet cards (Look v2 locked, Voice v1 locked with play button, Name rules v1), Episode overrides, "Used in Tanker Raja Parts 1–3", "New version of a facet" (warns about stale work and cost).

## Build mode

### Recipe builder

- Header: BUILD badge, breadcrumb (`Mohalla Mitra › Recipes › Part recipe`), "Draft of v4 · saved", Recipe/Canvas toggle, **Click-through test**, **Publish v5**.
- **Block palette** (drag from): AI steps (Write text, Draw an image, Animate an image, Voice a line, Make music, Agent with tools), **UI actions** (Pick one, Approve or redo, Fix an area, Listen and approve, Edit text, Fill a form), Logic (For each…, Only if…, Wait for all…), Tools · My blocks (Crop · Compress, Assemble Reel, Make thumbnail).
- **Recipe**: step cards with tags (AI step / UI action / Tool); "For each shot in the shot list" container; condition chips on connectors ("Only if shot.animate is yes", "Wait for all shots and voices"); drop zone highlight ("Release to add 'Approve or redo' here"); assistant proposal card highlighted with Apply / Discard; "Stuck? Ask the assistant" input.
- **Step settings** (for a UI action): Show / Beside it, **Buttons and where they go** table (Lock → Next step; Edit → Edit image (local); Crop → Crop tool; Try again → Draw the shot · max 4; + Add a button), Who decides, Review all on one screen, AI pre-checks first, **Preview this screen**.

### Canvas view

Same graph as boxes and arrows (React Flow): input → Draw the shot → Pick one panel (UI action, 4 buttons) → diamond "animate?" → Animate / Shot done; Edit image and Crop loop back to Pick (dashed arrows with limits; "retry ×4"). Selecting an arrow shows its condition as a rule and as the sentence the creator wrote. Key: white = AI step, amber = UI action, grey = tool, diamond = condition, dashed = goes back with a limit.

## One chat panel, scope follows selection

Nothing selected → episode agent. Click a shot → that shot's micro-agent. Click the series → project agent. The breadcrumb always shows who you're talking to and what they can change. In Build mode the same panel is the builder assistant.

## Monitoring screens (later)

Run status, cost so far per run/project, checker agreement rate per step (to justify raising trust), knowledge-base hits.
